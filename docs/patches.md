# 补丁说明

自制固件 = **原厂固件 + 补丁**。我们不改写整套固件，只做**可审计的字节级补丁**：

- 每条补丁带 `expect`（必须匹配的原字节）与 `replace`（写入的字节）；
- 对不上就**拒绝打**，绝不把补丁落到错的地方；
- 补丁表就是评审单元：一个地址 + 一个意图。

补丁表在源码里：`tool/crates/core/src/patch.rs`。

## 两条音量补丁

一共 **22 个字节**，都在出厂固件里被逐字节核对过。

### `no-volume-send` —— 不把音量发给屏幕

| | |
|---|---|
| 地址 | `0x5557`（8 字节） |
| 作用 | 去掉 8051 把 profile 音量字节（偏移 `0x31`）拷进「发给屏幕的设置包」那一次拷贝 |

被去掉的正是这段：

```asm
0x5557: 90 0F 12   MOV  DPTR,#0x0F12   ; 取 profile 的音量字段
0x555A: E0         MOVX A,@DPTR
0x555B: 90 0D BB   MOV  DPTR,#0x0DBB   ; 设置包里的音量位置
0x555E: F0         MOVX @DPTR,A
```

音量在固件里的完整链路（逐条核对过反汇编）：

| 步骤 | 位置 | 说明 |
|---|---|---|
| 载入 | flash `0xA431` → `xdata[0x0F12]` | profile 字段 `0x31` |
| 拷贝 | `0x5557` | 拷进设置包 `xdata[0x0DBB]` |
| 发送 | `0x5594`–`0x55CE` | 按 cmd `0x52` 逐字节发 128 B 给屏幕 SoC |

`xdata[0x0F12]` 全固件只有两处被读（载入 + 那次拷贝），`xdata[0x0DBB]` 只有一处被写
⇒ **那次拷贝是音量的唯一出口**。去掉它，屏幕就拿不到会变的音量，也就没有那条不对的
音量条。不塞哨兵值、不塞假值：设置包定长 128 B，那个字节照样发，但开机时 `0x89EE`
清零 `xdata 0x0000-0x0FFF` ⇒ 该值恒为 0。

### `no-volume-ods` —— 旋钮不再通知屏幕

| | |
|---|---|
| 地址 | `0x059C`（40 字节） |
| 作用 | 旋钮不再写 `xdata[0x0EE4]=0x81/0x82`、不再发 cmd `0x15`；HID consumer 用量照写 |

旋钮在主控上（`0x2812` 采 `P4.2`/`P0.7` 正交解码，方向写进 `xdata[0x0CA0]=9`）。
转到时主控同时做两件事：

1. 把 HID consumer 用量 `0xE9`/`0xEA` 写进 `RAM 0x57`/`0x58`（report id=2，16 位
   consumer 页）发给主机 ⇒ **系统音量照常增减**；
2. 把状态字节 `0x81`/`0x82` 写进 `xdata[0x0EE4]`，经 cmd `0x15` 通知屏幕 SoC，
   屏幕据此画音量条。

这条补丁只去掉后半截：两个出口都跳到 `0x05FA`（跳过 cmd `0x15` 发送与等应答，
只保留运行记录发布）⇒ 屏幕不再画音量，**主机侧音量指令不变**。

## 单元测试盯着

补丁表有单测守着，其中两条是安全网：

- `shipped_patches_match_the_dumps` —— 每条补丁的 `expect` 必须逐字节对得上仓库里的
  出厂 dump，否则**拒绝打**；
- `knob_patch_touches_nothing_outside_its_range` —— 应用补丁后，除了它自己那 40 字节，
  一个字节都不能变。
