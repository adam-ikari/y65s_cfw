# YD-Y65S 双芯片架构分析报告

> 对象：SINO WEALTH YD-Y65S（65%，带 240×135 彩色小屏 + 音量旋钮 + 2.4G/BT）
> **2026-10-21 更正**：音量旋钮在**芯片 A（主控）**上，不在芯片 B —— 见 §2.4。
> 证据来源：`firmware/YD-Y65S_full.bin`（64 KiB dump）、`build/fw_full.lst`（全量反汇编）、
> `analysis/`（`fwdis.py`/`usbdesc.py`）、ODM web 驱动（`build/odm/`）、真机实测记录。
> 证据分级：**[确认]** 有反汇编/描述符/实测直接支撑；**[推断]** 结构性强但缺直接证据；**[未解]** 尚未定位。

---

## 0. 一句话结论

YD-Y65S 是**双芯协同**的键盘，而且分工非常干净：

* **芯片 A = 主控 SH68F90A（8051）**：负责"感知与转发"——扫按键、出 USB HID、存配置、算灯效参数、
  跑 ISP，并且是**主机与模块之间唯一的桥**。
* **芯片 B = 模块 SoC（ODM 屏/无线模组）**：负责"表达与连接"——彩色小屏渲染、每键灯效、2.4G/BT 射频与电池、
  以及它自己的 RTC。音量旋钮在芯片 A 上（2026-10-21 更正，见 §2.4）。

两者之间只有**一条私有 UART**；主控的 USB 厂商通道（feature report 9，519 B）是主机侧唯一的入口，
厂商 app、ODM web 驱动、我们自己的工具都从这里进，再由主控转给模块。

**对我们的直接含义**：凡是"主控转发"的，我们都能做（校时、灯效、屏幕、恢复默认）；
凡是"模块内部逻辑"的（显示策略、音量量程、时钟走时），我们**改不了**，只能选择"不喂数据"。

## 1. 硬件身份

| | 芯片 A：主控 | 芯片 B：模块 |
|---|---|---|
| 型号 | SH68F90A（8051 内核，Sinowealth） | ODM 屏/无线模组 [推断] |
| 可取证性 | **完全可取证**：64 KiB code+flash dump、全量反汇编 | **不可取证**：固件既不可读也不可写（ISP 只覆盖芯片 A） |
| 物理职责 | 按键矩阵、USB HID、配置 flash、少量指示灯 PWM、UART 桥、**音量旋钮**（GPIO 正交解码） | 240×135 RGB565 TFT、每键 RGB、2.4G/BT、电池、RTC |
| USB 身份 | VID:PID `258a:019d`，2 个 HID 接口，320 mA | 无（它不直接连 USB） |

补充事实：**2.4G 接收器**是另一个 USB 设备 `258a:0150`，固件同样是 SH68F90A（64 KiB dump 存过），
即厂商在接收器上复用同一族 MCU。

## 2. 芯片 A（主控 SH68F90A）做什么

### 2.1 外设全集 [确认]

把固件里所有 SFR/XSFR 访问点枚举一遍（`analysis/fwdis.py sfr`），主控用到的外设**只有这些**：

| 类别 | 寄存器 |
|---|---|
| USB | `USBCON` `USBIF1/2` `USBIE1/2` `USBADDR` `EP0CON` `EP1CON` `EP2CON` `IEP0CNT` `OEP0CNT` `INSCON` |
| UART | `SBUF` `SCON` `SBRTH` `SBRTL` `SFINE` `PCON.6` |
| PWM | `PWM0x`–`PWM3x`（4 bank × 6 通道 × 2 路 duty）、`PWM4x`（SFR 空间）、`PWM4PERD*` |
| GPIO | `P0`–`P7` + 各自的 `CR/PCR/DRV` |
| 定时/中断 | `T2CON` `TL2` `IEN0/1` `IPH1/IPL1` `EXF0/1` `EXCON` |
| 存储/时钟 | `FLASHCON` `CLKCON` `PLLCON` `REGCON` |
| 模块桥 | `XPAGE` `IB_OFFSET` `IB_DATA` `IB_CON1..5` |

**没有**：LCD 控制器、SPI、I²C、ADC、编码器/捕获外设、射频前端。
⇒ 主控**不可能**自己画屏，更不可能做射频。
（「没有编码器**外设**」不能推出「读不了旋钮」：机械编码器只要两个 GPIO 软件解码 ——
2026-10-21 已据此推翻旋钮归属的旧结论。）

### 2.2 职责清单

| # | 职责 | 关键证据 | 等级 |
|---|---|---|---|
| 1 | 按键矩阵扫描（15 列 × 5 行 = 90 键，列优先） | 扫描派发 `0x35E8`、扫描序表 `0x0A90`（`col*8+slot`，未用槽 `0xFF`）、行读取 `0xB130`、键位表 `0xBC00-0xD800`（4 层 × 90 条 × 4 B） | 确认 |
| 2 | USB 键盘 HID（IF0） | 配置描述符 `0x46AA`：IF0 class 3/1/1，EP `0x81` IN 8 B，1 ms | 确认 |
| 3 | USB 厂商通道（IF1）＝主机侧唯一入口 | IF1 class 3/0/0，EP `0x82` IN 16 B；`SetFeature(feature 9, IF1, 519 B)` 经 `0x8363` → `0x6CA2/0xA650` 收进 `0x08F5` | 确认 |
| 4 | 配置存储（在用 profile / 出厂 profile） | 在用 `flash 0xA400..0xA47F`，出厂 `0x9983..0x9A02`，各 128 B；尾部 `5A A5` 标记 | 确认 |
| 5 | 灯效**参数**计算 | 灯效索引 profile `0x0A` → `xdata[0x0F65]`；码表 `0x0C00`（预设号 `0x00..0x14`）、`0x0C20`、`0x0C80`、`0x0CA0`；结果经 cmd `0x15`/`0x5E`/`0x5F` 交给模块 | 确认（计算在主控） |
| 6 | 与模块的 UART 桥 | 初始化 `0xB15A..0xB187`；组帧 `0x9BF9`；字节流 `0xBADB`→`0xA331`→`0xB2F3`；大块帧 `0xB204` | 确认 |
| 7 | ISP bootloader | 跳转桩 `0xB0ED`（`CLR IEN0.7` / `MOV B,#A5` / `MOV A,#5A` / `LJMP 0xFF00`），命令分发 `0x82EA` | 确认 |
| 8 | 无线档位**记账**与上报 | `xdata[0x0F29]`：`1`=USB、`0x25/0x35/0x45/0x55`=2.4G/BT1/BT2/BT3；切换入口 `0x116E/0x1265/0x127B`，槽号由 `xdata[0x0CA1]`(1..4) 决定 | 确认 |
| 9 | 少量状态指示灯 | 4 bank × 6 通道 × 2 duty 的 PWM；HID 描述符里有 5 个 LED 输出位（caps/num/scroll…） | 确认 |

### 2.3 主控明确不做的事 [确认（缺器件）]

* **不画屏**：没有显示控制器，flash 里也没有字模/位图数据。
* **（旧结论已推翻）不读旋钮**：2026-10-21 复核发现主控确实读旋钮 —— `0x2812` 采 `P4.2`/`P0.7`
  正交相并自己解码方向，见 §2.4。
* **不做射频**：没有任何 RF 相关寄存器。
* **不跑每键 RGB**：PWM 只有 24 通道 × 2 duty，远不够 68 键 × RGB；全片 PWM 写入点只有个位数。
  ⇒ **每键灯效的执行者是模块**（另见 §3）。
  （旁证：实测"发记录 `0x04`（=把 profile 推给模块）会让键盘 RGB 灭掉"，RGB 状态随发给模块的内容变化。）

### 2.4 音量旋钮在主控上 [确认，2026-10-21 更正]

§2.1 的"主控没有编码器/捕获外设"只说明**不能用专用外设**，不能推出"读不了旋钮"——
机械旋转编码器只要两个 GPIO 软件解码。复核固件后，旋钮确实在主控上：

| 地址 | 作用 |
|---|---|
| `0x2812` | 旋钮采样：`MOV C,P4.2`（相 A）+ `MOV C,P0.7`（相 B）→ `RAM 0x20` bit0/bit1 |
| `0x2833` | 与上次采样 `xdata[0x0BAF]` 比较，变了才继续 |
| `0x283E` | 6 位历史寄存器 `xdata[0x0BA9]`：`hist = (hist<<2 & 0x3F) + 新样`（3 个 2 位相 History） |
| `0x284C` | `ADD A,#0xF9` 判 `hist==7` → 一个方向（`0x2991`） |
| `0x2853` | `ADD A,#0xFC` 判 `hist==11` → 另一个方向（`0x285A`） |
| `0x2876`/`0x29B0` | 方向 → `xdata[0x0CA0]=9`、`xdata[0x0CA1]=1|2`，并置 `BITS_39` |
| `0x04C4` | 派发表 `0x04A9` 索引 9 → `LJMP 0x0594` |

`P4.2`/`P0.7` 都不在 15×5 键矩阵里（列：P6.0-P6.7、P5.0-P5.2、P5.7、P4.0、P7.7、P4.5；
行：P7.1-P7.3、P5.3、P5.4），两脚都开上拉（P4PCR bit2 / P0PCR bit7）—— 正好是开漏输出编码器的接法。

`0x0594` 这一段同时做两件事：

| 去向 | 内容 | 后果 |
|---|---|---|
| HID（主机） | `RAM 0x57` = `0xE9`/`0xEA`（consumer 页 16 位用量 = Volume Increment/Decrement），report id 2 | 主机系统音量增减 |
| cmd `0x15`（模块） | `xdata[0x0EE4]` = `0x81`/`0x82`（状态类 8 = 音量变化） | 屏幕画音量条 |

⇒ 要"屏幕不画音量、主机照常调音量"，只需切断第二条：补丁 `no-volume-ods`（`0x059C`，40 B）
不写 `0x0EE4`，并让旋钮分支跳到 `0x05FA`（跳过 cmd `0x15` 发送与等应答，只保留运行记录发布）。

## 3. 芯片 B（模块）做什么

模块的固件读不出来，下列职责全部由**主控侧的行为**反推。

| # | 职责 | 反推依据 | 等级 |
|---|---|---|---|
| 1 | TFT 渲染（240×135 RGB565 **大端**） | 主控无显示器件却能把整屏内容推上去并显示（实测推纯红成功）；上传协议 `0x0D`→`0x0C`→`0x0D`，节拍 120/50/50/500 ms | 确认 |
| 2 | 每键 RGB 灯效执行 | 内置 21 个预设（码表 `0x0C00` 段 `0x00..0x14`）经 cmd `0x5E/0x5F`/`0x62/0x63` 下发；主控 PWM 通道数不够 | 推断（强） |
| 3 | 2.4G / BT1 / BT2 / BT3 射频 + 电池 | 主控只"记账"档位；ODM 设备信息里带 `batteryLevel`（`l[17]`），该信息由键盘转发给主机 ⇒ 电池状态只有模块知道 | 推断（强） |
| 4 | ~~音量旋钮~~ → **在主控** | 主控 `0x2812` 采 `P4.2`/`P0x7` 正交相并解码；旋钮不在模块 | 确认（2026-10-21 更正） |
| 5 | 自己的 RTC（屏幕上的时间） | 屏幕时间由 ODM 的 `setTftDateTime`/`setLedDateTime` 设定（11 B 载荷）；模块时钟会漂（实测屏幕比 PC 快 4–7 分钟，约 +1.5%） | 确认 |
| 6 | 应答与状态回报 | 主控发每个字节帧都要等模块 `0x55` 应答才继续 ⇒ 模块是 ODM 兼容应答端；模块还会发 `0x5A` 魔数的私有短报文（≤14 B） | 确认 |

### 3.1 模块暴露给主控的能力面（ODM 命令集）[确认]

ODM web 驱动（`build/odm/`）暴露了一整套模块能力，命名即接口：

`setTftDateTime` `setTftScreenInfo` `setTftUserAnimation` `setTftBuiltInIndex` `setLEDEffect`
`setLedDateTime` `setLedSyncAnimation` `setLedUserAnimation` `setSideLight` `setLightBox`
`setMusicData` `setGifLighting` `setKeyData` `setFnKeyData` `setMacroData` `setTriggerConfig`
`setCustomLEDData` `setDotMatrixMode` `setGameMode` `setMagneticAxisDKSData/RT`
`start24G*Listener` `startCalibration*` `startDeviceStateListener` `startResetListener` `resetAll`

⇒ 模块的能力远不止"一块屏"：它管灯效矩阵、音箱/音乐律动、磁轴、宏、触发器、侧灯、24G 状态、标定。
**这台键盘只暴露了其中一部分**（屏 + 灯 + 无线 + 旋钮 + 时钟）。

## 4. 两颗芯片之间的接口

### 4.1 物理层 [确认]

* 硬件 UART，mode 1（`SCON=0x50`，REN=1）；`SBUF=0xAA`、`SCON=0xD8`（运行态）。
* 初始化 `0xB15A..0xB187`：`SBRTH=0xFF`、`SBRTL=0xFB`、`SFINE=0x0C`（≈115200），开 `IEN1.6`。
* `P4.1` 被反复拉低再切回输入 ⇒ 链路唤醒/握手脚；`P0.5` 是"是否启用该链路"的跳线（`JB P0.5`）。

### 4.2 帧格式 [确认]

| 方向 | 格式 | 组帧/校验 |
|---|---|---|
| 主控 → 模块 | `50 <cmd> <len> <payload…> <sum>` | 组帧 `0x9BF9`；`sum` = cmd+len+payload 的 8 位累加和（`0xB607`） |
| 主控 → 模块（大块） | `50 81 <size_hi> <size_lo>` + payload | `0xB204` 组帧；payload 缓冲 `0x08F5..0x0AFC`＝520 B，线上共 524 B |
| 主控 → 模块（字节流） | 每字节一帧 `50 <cmd> 01 <b> <sum>` | `0xBADB` → `0xA331`（白名单查表）→ `0xB2F3`（IB 硬件寄存器直发）；**必须等模块 `0x55` 应答**才发下一字节（流控） |
| 模块 → 主控 | 首字节 `0x5A`（私有）或 `0x55`/`0xAA`（ODM 应答） | 判别 `0xB9B0`；私有报文 magic `xdata[0x1130]==0x5A`，长度 ≤14 B，`xdata[0x0F61]=1` 表示收齐 |

模块 → 主控私有短报文的落地（`0xB4FC`）：

* 类型 `0x00` → 载荷写 `xdata[0x0F18]`（**事件码**，主控据此改状态，例：`0x12`=链路档位变化、`0x22`=另一类事件）
* 类型 `0x02` → 载荷写 `xdata[0x1155]`（低 3 位被主控读进 `xdata[0x0EE4]` 参与状态上报）
* 其它类型 → 置 `xdata[0x0F16] |= 0x20`（"有情况"标志）

### 4.3 主控 → 模块 命令全集

**A. 状态/事件类**（主控把自身状态快照告诉模块；调用点集中在 `0x008B..0x06EE`）[确认]

| cmd | len | 载荷来源 | 推测语义 |
|---|---|---|---|
| `0x0A` | 14 | `xdata 0x0EE4` | 完整状态包（最大的一帧） |
| `0x04` | 4 | `xdata 0x0EE4` | 状态片段（含计时/档位） |
| `0x15` | 2 | `xdata 0x0EE4` | **灯效模式/序号**（`[0x0F64]` 或 `[0x0CA1]`） |
| `0x02` | 1 | `xdata 0x0EE4` \| `0x80` | 状态位 |
| `0x08` | 1 | `xdata 0x0EE4` | 状态位 |
| `0x13` | 1 | `xdata 0x0EE4` \| `0x08` | 状态位 |
| `0x17` | 1 | `xdata 0x0EE4` \| `0x80` | **链路/模式相关**（与 `xdata[0x0F18]==0x22` 联动） |
| `0x18` | 1 | `xdata 0x0F6A` | 链路状态值 |
| `0x1A` | 1 | `xdata 0x0C2C` | profile 派生量（`[0x0C2A]`=值+2） |
| `0x1B` | 1 | `xdata 0x0EE4` | 状态位 |
| `0x03` | 0 | — | 无载荷事件（配合 `xdata[0x0ED7]` 的 bit2） |

**B. 数据类**（ODM 命令，**模块 cmd = ODM cmd + 0x1E**）[确认]

| 模块 cmd | ODM cmd | 载荷 | 用途 |
|---|---|---|---|
| `0x52` | `0x34` | 128 B | **设备/屏幕 profile**（`0x0D8A` 起，逐字节发） |
| `0x54` | `0x36` | 2 B | 码表（`0xAA00`） |
| `0x56` | `0x38` | 126 B | TFT 代码表（`0xAD7A`），分两轮（122+126 B） |
| `0x5E/0x5F` | `0x40/0x41` | 1 B ×2 轮 | 灯效预设（表 `0x0C00`/`0x0C20`） |
| `0x62/0x63` | `0x44/0x45` | 1 B ×2 轮 | 灯效预设（表 `0x0C80`/`0x0CA0`） |
| `0x66/0x67` | `0x48/0x49` | 0 | — |
| `0x6A/0x6B` | `0x4C/0x4D` | 0 | — |
| `0x6E..0x75` | `0x50..0x57` | 0 | ODM 数据通道（主机侧记录 `0x05` 可选 `0x6E..0x75`） |
| `0x81` | — | 520 B | **大块帧**：主机 519 B 记录整块转发（记录 `0x0B/0x0C/0x0D`） |

**C. 流控与忙标志** [确认]

* 主机记录 `0x04`/`0x05` 在 `xdata[0x0F2F]==0x5A`（模块忙）时**整条丢弃**（`0x7E6B`/`0x8724`）。
* 每次字节帧都要等 `0x55` 应答；超时计数 `xdata[0x0F6E]`，上限 `0x32`。

### 4.4 主机侧通道（我们真正能碰的那一半）[确认]

`SetFeature(feature 9, IF1, 519 B)` → 记录分发器 `0x6346` → 跳表 `0x6373`：

| 记录 | 去向 | 备注 |
|---|---|---|
| `0x03` | 子分发 `0x923E/0x92D8/0x8DB3/0x8D13` | 对应模块 cmd `0x62/0x66/0x6A/0x5E`（8 B 记录） |
| `0x04` | `0x7E5B` | 128 B → cmd `0x52`（profile）逐字节发 |
| `0x05` | `0x8715` | 512 B → cmd `0x6E+payload[4]`（`payload[4]`∈0..7）逐字节发 |
| `0x06` | `0x6F1F` | 代码表 → cmd `0x56`（126 B ×2 轮） |
| `0x08` | `0x6B57` | **RAM 配置（会持久化到 flash）⚠ 曾导致"全键失灵"** |
| `0x0A` | `0x6DE2` | cmd `0x54` |
| `0x0B/0x0C/0x0D` | `0x6474/0x644D/0x641B` | 整块 520 B → cmd `0x81`（屏幕内容通道） |

所有记录的数据窗都从 `payload[7]` 开始；`payload[0]`=记录号、`payload[4]`=子参数。

## 5. 六条数据流：谁产生、谁执行、谁是权威

| 功能 | 产生 | 搬运 | 执行 | 权威方 | 通道 |
|---|---|---|---|---|---|
| **按键** | 矩阵（芯片 A） | 芯片 A | 芯片 A | 芯片 A | USB IF0 标准键盘报告 |
| **灯效** | 主机（app/ODM/我们的工具）写 profile `0x0A`/`0x33` | 芯片 A 读 profile → 查内置码表 → 算参数 | **芯片 B** | 参数：芯片 A；执行：芯片 B | cmd `0x15`/`0x5E`/`0x5F`/`0x62`/`0x63` |
| **屏幕内容** | 主机（ODM 驱动/厂商 app/我们） | 芯片 A（feature 9 → 记录 → 0x81/0x52） | **芯片 B**（渲染） | 内容：主机；渲染：芯片 B | 记录 `0x0B/0x0C/0x0D` → cmd `0x81` |
| **音量** | 主机 app 读系统音量 ×100 → profile `0x31` | 芯片 A（唯一出口 `0x5557`）→ 设置包 `0x31` | **芯片 B**（画条） | 音量本体：操作系统 | cmd `0x52`（设置包） |
| **旋钮调音量** | **芯片 A**（`0x2812` 采 P4.2/P0.7 解码方向） | 芯片 A 分两路：① HID consumer 用量 `0xE9/0xEA` → USB；② 状态字节 `0x81/0x82` → cmd `0x15` → 芯片 B | ① 主机（系统音量）② 芯片 B（屏幕音量条） | 主机 | USB HID（主机侧）/ cmd `0x15`（屏幕侧） |
| **时钟** | 主机（PC 时间） | 芯片 A（记录通道） | **芯片 B**（自己的 RTC，会漂） | 时间：主机；走时：芯片 B | ODM `setTftDateTime`（11 B：`5A 01 5A yy mo dd hh mi ss wd`） |
| **无线档位** | 主机按键 / 芯片 A 记账 | 芯片 A（`xdata[0x0F29]`）→ cmd `0x17`/`0x18` | **芯片 B**（射频） | 射频：芯片 B；记账：芯片 A | UART 事件帧 |

⇒ 规律：**芯片 A 永远是"搬运工 + 记账员"，芯片 B 永远是"执行者"**。
主机能改变的一切，前提是芯片 A 愿意转发。

## 6. 证据分级汇总

**[确认]**

* 主控外设全集（§2.1）⇒ 无显示/无射频（**无旋钮这条已推翻**，见 §2.4）。
* USB 拓扑：IF0 = 8 B 键盘，IF1 = 16 B 厂商 + feature 9（519 B）。
* 模块链路帧格式、命令全集、流控、忙标志。
* 音量的完整链路：flash `0xA431` → `xdata[0x0F12]` → **唯一出口** `0x5557` → 设置包 `0x0DBB` → cmd `0x52`。
  `xdata[0x0F12]` 全片只有两处被读，`xdata[0x0DBB]` 只有一处被写。
* 灯效索引 → 内置码表 → 交给模块。
* 无线档位的取值与切换路径。
* 模块时钟漂移（实测 4–7 分钟）与 11 B 时间载荷。

**[推断（强）]**

* 芯片 B = ODM 屏/无线模组（协议兼容 + web 驱动命令面）。
* 每键 RGB 由芯片 B 执行。
* 音量旋钮电气上挂在**芯片 A**（`P4.2`/`P0.7` 两个 GPIO，2026-10-21 更正）。

**[未解]**

* `setTftDateTime` / `setLedDateTime` 的 ODM 命令号落在 8051 哪条可达通道（⇒ 校时命令仍未定位）。
* profile `0x3A..0x7D` 那 68 B（疑似 34 个 RGB565）的含义。
* profile 里 `0x16/0x18/0x1F/0x31/0x35/0x36/0x37` 各字段含义（`0x31` 已确认是音量）。
* 芯片 B 对"音量恒为 0"、"时间不刷新"的反应（只能真机看）。
* 旋钮的物理位置（在芯片 A 上，但左右侧 dump 里查不到）。

## 7. 对我们项目的影响

1. **能做的**（主控转发 ⇒ 我们能转发）：校时、灯效、屏幕内容、恢复默认、固件刷写与补丁。
2. **做不了的**（芯片 B 内部）：显示策略、音量量程、时钟走时精度。
   ⇒ 唯一 lever 是"不喂数据"（音量补丁 `no-volume-send`：`0x5557` 那次拷贝整个去掉）。
3. **补丁落点唯一且可审计**：音量在固件里只有一个出口（`0x5557`），`expect` 字节可在两份真实 dump 上双校验。
4. **常驻工具的价值被放大**：芯片 B 的 RTC 会漂 ⇒ 一次性对时不够；工具常驻 + 开机自启 ⇒ 可以定时重发时间、
   并持续把系统音量推给键盘（此时屏幕上的音量与系统一致）。
5. **风险**：芯片 B 不可验证 ⇒ 任何"它会怎么反应"的判断都必须真机确认；这也是当前唯一被隧道卡住的事。
